# 01. 문서 작성 규칙

위키 문서를 만들거나 고칠 때 지키는 규칙이다. 도구용 상세 규칙의 정본은 레포 `CLAUDE.md`, 사람이 보는 규칙은 이 문서다.

## 말투

- **강의 자료식 평서체(한다체)** 를 기본으로 한다: `~한다 / ~이다 / ~본다 / ~하면 된다`.
- 같은 섹션·기존 문서가 합니다체면 그 어미에 맞춰 **한 문서 안에서 일관**되게 쓴다(혼용 금지).
- **AI 어시스턴트식 말투를 쓰지 않는다.** 금지: 1인칭("제가"), 대행("도와드릴게요"), 독자에게 질문("~할까요?"), 권유·영업("원하시면 ~", "~하시면 됩니다"), 군더더기 이모지 장식, 과장("아주 잘"), 메타 코멘트.
- 독자를 부르지 말고 **대상을 서술**한다. (×) "Grafana를 보세요" → (○) "Grafana에서 5xx율을 본다."

## 구조(IA)

- 최상위: `시작하기`(신입 온보딩) · `Guide`(이해) · `Manual`(도구 사용법) · `Convention` · `Domains` · `Wiki` · `Lecture`.
- **Guide = 서비스·개념**: 01 인프라와 플랫폼 / 02 서비스 운영 / 03 관측과 SRE.
- **Manual = 도구 사용 절차**. 서비스별 운영 절차는 Guide의 서비스 폴더에, 도구 사용법은 Manual에 둔다.

## 넘버링

- **1부터 빈칸 없이 연속**, **두 자리 zero-pad**(`01, 02, … 10`). 한 자리면 WikiJS 트리(문자열 정렬)에서 `10`이 `2`보다 앞에 온다.
- 같은 레벨은 모두 `NN. 제목/index.md`(폴더+인덱스)로 통일한다. 폴더와 단일 파일을 같은 레벨에 섞지 않는다.
- 항목 삽입·삭제 시 뒤 번호를 당기거나 밀고, **폴더명·frontmatter title·H1·문서 간 링크·Page Tree**를 함께 갱신한다.

## 정확성

- 인프라·서비스·솔루션 설명은 **실제 소스(루트 `gitops/` 매니페스트, 각 서비스 레포)와 대조**해 쓴다. 버전·접속 URL·연결관계는 추정하지 않는다.
- 미확정 값은 `TODO(확정 필요)`, 개선 과제(평문 시크릿·SPOF 등)는 `⚠️`로 남긴다.

## 발행·검증

- 발행 경로: `vault/`(GitHub) → 클러스터 `content-sync`(60초 주기 `main` pull) → WikiJS. **`main` 머지 = 운영 반영.**
- 변경 후: 상대 링크 깨짐 0, `python3 scripts/wiki_wikijs_sync.py sync --dry-run`으로 미리보기.
