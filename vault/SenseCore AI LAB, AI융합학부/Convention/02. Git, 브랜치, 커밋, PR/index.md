# 02. Git, 브랜치, 커밋, PR

코드·문서 변경의 협업 규칙이다.

## 브랜치

- 형식: **`<깃 닉네임 축약>/<이슈 번호>`**.
- 닉네임 축약: 깃 닉네임에서 뒤 숫자·접미사를 떼어 짧게 쓴다. 예) `say828` → `say`.
- 이슈 번호: 프로젝트 이슈 트래커의 번호를 쓴다. 예) 이슈 142 → **`say/142`**.
- `main`은 보호 브랜치다. 직접 푸시하지 않고 브랜치 → PR로 들어간다.

## 커밋 메시지

- **Conventional Commits 타입 접두**를 쓴다: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:` 등.
- 형식: `type: 요약` (필요하면 `type(scope): 요약`). 요약은 한글로 명확하게 쓴다.
- 예) `feat: 발화 실패 Alerta 알림 추가`, `fix: KMC 요청번호 포맷 수정`, `docs: 관측·SRE 섹션 정리`.

## PR

- **PR 단위로 작업한다.** 한 PR은 하나의 목적만 담아 작고 명확하게 유지한다.
- **리뷰는 에이전트에게 위임한다.** PR 단위로 에이전트 특화 리뷰(코드 리뷰 에이전트)를 돌려 검토한다.
- `main` 머지는 곧 운영 반영(GitOps·위키 모두)이므로, 머지 전 검증(빌드·dry-run·링크)을 통과시킨다.
