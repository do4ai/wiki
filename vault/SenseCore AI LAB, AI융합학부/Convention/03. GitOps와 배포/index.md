# 03. GitOps와 배포

배포는 클러스터를 직접 고치지 않고 레포를 고쳐서 한다. 개념은 [Guide 01. 인프라와 플랫폼 / GitOps 운영 모델](../../Guide/01. 인프라와 플랫폼/04. GitOps 운영 모델 가이드/index.md).

## 원칙

- **배포 정본은 `gitops` 레포다.** 레포의 매니페스트가 "원하는 상태"이고, ArgoCD가 클러스터를 그 상태로 수렴시킨다.
- **`main` push/merge = 배포 신호.** 머지하면 ArgoCD가 반영한다.
- 클러스터를 `kubectl`로 직접 바꾸지 않는다(임시 디버깅 제외). 바꾸려면 레포를 바꾼다.

## 동기화 정책

- **prod의 `do4i`·`passv` Application은 자동 동기화를 끈다(수동 sync).** 운영 반영 시점을 사람이 통제한다.
- dev와 그 외 앱은 자동 동기화를 쓴다.

## 이미지

- overlay `images:`에 **태그 + digest를 핀**한다. 가변 태그(`latest`)로 운영 배포하지 않는다.
- 레지스트리는 [04. 네이밍과 환경](../04. 네이밍과 환경/index.md) 참고.

## 롤백

- 직전 정상 **이미지 태그/digest로 레포를 되돌려 커밋**하거나, ArgoCD에서 이전 리비전으로 sync 한다. 정본은 Git이다.
- 자동 동기화를 끈 앱은 롤백 후 sync 시점을 직접 잡는다.

## 검증

- 매니페스트 변경 후 `kubectl kustomize <overlay>`로 렌더가 되는지 확인한다. 알림 규칙은 가능하면 `promtool check rules`.
